# Site-Wide Mobile UX Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the mobile jump-nav scroll-target bug at its root, make the dish jump-nav usable on a phone (overflow affordance + current-dish awareness), stop the shopping-list picker from burying its own output, and extend the same sticky-offset fix to the homepage category nav plus a small tap-target pass.

**Architecture:** CSS custom properties (`--header-h`, `--jump-h`) become the single source of truth for sticky-bar heights, replacing hardcoded magic numbers scattered across two stylesheets. Two React components (`DinnerChecklist`, `ShoppingListBuilder`) get small, targeted state additions (active-dish tracking via `IntersectionObserver`, a collapsible picker panel) — no new shared component abstractions, no new dependencies.

**Tech Stack:** Astro 4 (static site), React islands (`client:load`), plain CSS (no preprocessor, no Tailwind), Vitest for `src/lib` logic tests only (no component/DOM test harness exists in this repo — see Global Constraints).

**Spec:** `docs/superpowers/specs/2026-08-30-mobile-ux-v2-design.md`

## Global Constraints

- **No new npm dependencies.** Do not add Playwright, `@astrojs/check`, `@testing-library/react`, jsdom, or anything else to `package.json`. This repo has no component/DOM test harness (`vitest.config.ts` uses `environment: 'node'`, and only covers `src/**/*.test.ts` under `src/lib`) — that is intentional per the spec's Approach A decision, not a gap to fill in this plan.
- **CSS/behavior only.** No content, schema, or routing changes.
- **No font shrink** below current sizes; legibility preserved (carried over from the prior 2026-06-17 mobile spec, still applies).
- **Verification is build + grep + manual browser check**, matching this repo's existing convention (see the prior plan at `docs/superpowers/plans/2026-06-17-mobile-ux.md` for precedent) — not a new automated browser-test suite.
- Do NOT touch `vitest.config.ts`, `.gitignore`, `package.json`, or unrelated files.
- All measurements below (heights, offsets) were taken directly against the running dev server during design — use them exactly as given, don't re-derive different numbers.

- [ ] **Step 3: Add the IntersectionObserver effect**

Right after the existing `useEffect` that loads `checked` from `localStorage` (the one with dependency `[storageKey]`), add a new effect:

```tsx
  useEffect(() => {
    const observer = new IntersectionObserver(
      (entries) => {
        const visible = entries.filter((e) => e.isIntersecting);
        if (visible.length === 0) return;
        const topMost = visible.reduce((a, b) => (a.boundingClientRect.top < b.boundingClientRect.top ? a : b));
        const index = sectionRefs.current.findIndex((el) => el === topMost.target);
        if (index !== -1) setActiveDish(index);
      },
      // 132px clears the sticky site header (60-68px) + sticky jump nav (~61px) across
      // breakpoints; the -70% bottom margin keeps the trigger band near the top of the
      // viewport so only the dish currently under the sticky bars counts as active.
      { rootMargin: '-132px 0px -70% 0px', threshold: 0 },
    );
    for (const el of sectionRefs.current) {
      if (el) observer.observe(el);
    }
    return () => observer.disconnect();
  }, [dishes.length]);

  useEffect(() => {
    linkRefs.current[activeDish]?.scrollIntoView({ inline: 'nearest', block: 'nearest' });
  }, [activeDish]);
```
